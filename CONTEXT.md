# Сервис мониторинга ошибок

Документ фиксирует единый язык для отдельного self-hosted-сервиса, который принимает ошибки из React-приложений компании и помогает разработчикам находить и устранять их причины.

## Термины

**Рабочее пространство (Workspace)**:
Граница доступа, внутри которой находятся сотрудники компании и наблюдаемые проекты. В первой версии одна установленная копия сервиса содержит ровно одно рабочее пространство.
_Не использовать как синонимы_: клиент, пользователь приложения, аккаунт

**Участник (Member)**:
Сотрудник, принявший приглашение в рабочее пространство. Он входит по email и паролю либо через привязанный Google-аккаунт и имеет роль и членство в командах.
_Не использовать как синонимы_: клиент, конечный пользователь

**Учётная запись (Account)**:
Способ, которым человек подтверждает свою личность при входе. Одна учётная запись может использовать пароль и/или привязанный Google-аккаунт; сама по себе она не даёт доступ к проектам без активного участия в рабочем пространстве.
_Не использовать как синонимы_: рабочее пространство, роль, команда

**Приглашение (Invitation)**:
Отправляемое по email одноразовое разрешение создать учётную запись или присоединить существующую. Действует 48 часов и заранее содержит роль и команды.
_Не использовать как синонимы_: сессия, постоянная ссылка, публичная регистрация

**Второй фактор (TOTP)**:
Короткий одноразовый код из приложения-аутентификатора, который проверяется после пароля. Для Owner обязателен; не является входом через Google.
_Не использовать как синонимы_: Google-вход, пароль, recovery-код

**Конечный пользователь (End User)**:
Человек, который работает в одном из наблюдаемых React-приложений. Он не является участником сервиса мониторинга и не получает доступ к личному кабинету.
_Не использовать как синонимы_: участник, разработчик

**Проект (Project)**:
Отдельное наблюдаемое React SPA со своим адресом приёма ошибок, разрешёнными доменами, релизами, группами ошибок и командами, которым разрешён доступ.
_Не использовать как синонимы_: рабочее пространство, сайт

**Команда (Team)**:
Группа участников внутри рабочего пространства. Участник может состоять в нескольких командах, а проект может быть доступен нескольким командам. Owner видит все команды и проекты установки.
_Не использовать как синонимы_: роль, проект, рабочее пространство

**Событие ошибки (Error Event)**:
Один конкретный случай исключения или сообщения уровня `error`/`fatal`, присланный проектом.
_Не использовать как синонимы_: группа ошибок, лог, задача

**Группа ошибок (Issue)**:
Набор событий, которые сервис считает проявлениями одной и той же причины. Это основной объект в списке ошибок личного кабинета.
_Не использовать как синонимы_: событие, лог, тикет

**Отпечаток ошибки (Fingerprint)**:
Стабильное вычисляемое значение, по которому события объединяются в одну группу ошибок.
_Не использовать как синонимы_: идентификатор события, хеш тела запроса

**Решение ошибки (Resolution)**:
Ручная отметка участника о том, что причина группы ошибок считается устранённой. Сами сохранённые события при этом не удаляются.
_Не использовать как синонимы_: удаление, игнорирование

**Регрессия (Regression)**:
Новое событие в уже решённой группе. Сервис автоматически снова открывает такую группу и помечает её как вернувшуюся ошибку.
_Не использовать как синонимы_: повтор запроса, дубликат

**Релиз (Release)**:
Неизменяемый идентификатор конкретной сборки проекта, связывающий события, развертывание и карты исходного кода. В MVP основа идентификатора — полный Git commit SHA.
_Не использовать как синонимы_: окружение, ветка, деплой

**Окружение (Environment)**:
Метка места, где работает сборка, например `production`, `staging` или `development`. Окружение не заменяет проект или релиз.
_Не использовать как синонимы_: релиз, домен, ветка

**DSN**:
Публичная строка подключения, содержащая адрес приёма ошибок, идентификатор проекта и публичный ключ отправки. DSN разрешает только присылать события и никогда не даёт права их читать.
_Не использовать как синонимы_: секрет, deploy key, пользовательский токен

**Публичный ключ отправки (Public Ingestion Key)**:
Случайный заменяемый, но не секретный ключ из DSN. Он помогает выбрать проект, применить его лимиты и при необходимости отключить старый источник.
_Не использовать как синонимы_: секретный ключ, deploy key

**Токен загрузки source maps (Source Map Upload Token)**:
Секретный отзывной токен с единственным правом: загружать source maps для одного проекта из CI.
_Не использовать как синонимы_: DSN, публичный ключ, сессия участника

**Разрешённый origin (Allowed Origin)**:
Зарегистрированная для проекта комбинация протокола, домена и порта, например `https://app.example.com`. Используется как дополнительный фильтр запросов из браузера, но не доказывает, что запрос создал наш код.
_Не использовать как синонимы_: авторизованный домен, доверенный отправитель

**Source map (карта исходного кода)**:
Закрытый артефакт сборки, который связывает координаты в сжатом JavaScript с файлами и строками исходного кода.
_Не использовать как синонимы_: исходный файл, релиз

**Debug ID**:
Случайный идентификатор, одинаково записанный CI в JavaScript-файл и соответствующий ему source map. По нему сервис безошибочно выбирает карту именно от той сборки, в которой произошла ошибка.
_Не использовать как синонимы_: релиз, Git SHA, идентификатор события

**Безопасная история перед ошибкой (Safe Breadcrumbs)**:
Короткая ограниченная цепочка технических действий непосредственно перед ошибкой — например, смена маршрута или неуспешный API-запрос — без текстов страниц, тел запросов, заголовков, query-параметров и пользовательского ввода.
_Не использовать как синонимы_: запись действий пользователя, session replay, полный лог
