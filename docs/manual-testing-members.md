# Проверка ролей, команд и приглашений

## Запуск

1. Из корня проекта выполните `yarn local:start`. Текущая сборка и Mailpit подготовлены. Повторный запуск не пересобирает приложение и не создаёт аккаунт заново.
2. Откройте кабинет: **https://monitor.localhost:8443**. Используйте сохранённые email, пароль и аутентификатор Owner. Если это совершенно новая установка, один раз пройдите [setup](local-preview.md).
3. Откройте локальную почту: **http://127.0.0.1:8025**. Точный адрес также напечатает команда запуска. Логин для почты не нужен; все письма остаются здесь, на реальные адреса они не отправляются.
4. Оставьте Owner в основном профиле браузера. Для приглашённых участников используйте отдельный профиль или другой браузер. Все окна инкогнито одного браузера обычно разделяют сессию: для последовательной проверки выходите из предыдущего аккаунта.

После изменений исходников сборку обновляют командой `yarn checks`. Для обычных повторных запусков достаточно `yarn local:start`. Остановка — `yarn local:stop` или Ctrl+C.

## Подготовка команд и проектов

1. Под Owner откройте **Settings → Confirm your identity**: введите пароль и новый шестизначный код. Подтверждение действует пять минут. Если форма позже попросит подтвердиться снова, повторите этот шаг. Уже использованный TOTP-код повторно не принимается.
2. В **Projects → Create project** создайте два проекта: `Frontend demo` / slug `frontend-demo` и `Backend demo` / slug `backend-demo`. Если они уже есть, используйте их. Allowed origins для локальных примеров: `https://browser.monitor.localhost:8443` и `https://react.monitor.localhost:8443`, каждый с новой строки. Сохраните DSN каждого проекта, он показывается один раз.
3. В **Teams → Create team** создайте `Frontend`, отметив только `Frontend demo`, и `Backend`, отметив только `Backend demo`. Участников пока можно не выбирать.
4. Новый проект автоматически входит в первоначальную команду. Приглашения ниже выдавайте в `Frontend`/`Backend`, не в первоначальную команду. При необходимости уберите проекты из первоначальной команды через **Edit team** после назначения новых команд. У проекта должна остаться хотя бы одна команда.
5. На `https://browser.monitor.localhost:8443` вставьте DSN Frontend в **Connect**, отправьте ошибку. Затем подключите DSN Backend и отправьте другую ошибку. У Owner в Issues должны появиться обе группы.

## Приглашение Developer

1. В **Members → Invite a teammate** введите `developer@example.test`, выберите **Developer** и команду **Frontend**. Нажмите **Send invitation**.
2. В таблице Invitations появится запись `pending`; доставка сначала `pending`/`processing`, затем `sent`. Обновите страницу для актуального статуса.
3. В Mailpit откройте письмо **Your GetException invitation** для этого адреса. Скопируйте ссылку и откройте её в профиле будущего Developer. Сохраняйте часть после `#`: это часть ссылки приглашения.
4. На странице видны workspace, отправитель, Developer, Frontend и замаскированный email. Нажмите **Create an account · verify email**.
5. В Mailpit появится второе письмо: **Confirm your email for GetException**. Откройте его ссылку в том же профиле Developer и нажмите **Confirm my email**.
6. Только теперь появится форма имени и пароля. Укажите имя, придумайте пароль из 12–128 символов и нажмите **Create account and join**.
7. Войдите как `developer@example.test` с этим паролем. Поле аутентификатора оставьте пустым: для Developer/Viewer он добровольный.

Ожидается: аккаунт создан, приглашение у Owner стало `accepted`, участник входит в Frontend. По исходной ссылке второй аккаунт создать нельзя. Обновление страницы, которая уже убрала токен из адресной строки, может потребовать заново открыть ссылку из письма.

## Проверка доступа

| Проверка                             | Owner                          | Developer в Frontend       | Viewer в Frontend                        |
| ------------------------------------ | ------------------------------ | -------------------------- | ---------------------------------------- |
| Overview, Issues, Releases, Projects | Все проекты                    | Только Frontend demo       | Только Frontend demo                     |
| Resolve / Reopen                     | Доступны                       | Доступны для Frontend demo | Кнопок нет, изменение запрещено сервером |
| Teams                                | Все, создание и редактирование | Только свои, просмотр      | Только свои, просмотр                    |
| Members, приглашения, Audit log      | Доступны                       | Недоступны                 | Недоступны                               |
| Создание проекта                     | Доступно                       | Недоступно                 | Недоступно                               |
| Settings                             | Свой аккаунт                   | Свой аккаунт               | Свой аккаунт                             |

1. В профиле Developer проверьте таблицу выше. По прямой ссылке Owner на проект, ошибку или релиз Backend должна открыться страница отсутствующего ресурса. Прямые `/members`, `/audit-log`, `/teams/new`, `/projects/new` тоже недоступны.
2. Закройте ошибку Frontend через **Resolve**, затем откройте через **Reopen**. У Owner статус должен измениться.
3. Повторите приглашение для `viewer@example.test`, роль **Viewer**, команда **Frontend**. Пройдите два письма, регистрацию и вход в отдельном профиле. Данные доступны, кнопки Resolve/Reopen отсутствуют.
4. Под Owner откройте **Members → имя Developer**, добавьте Backend и сохраните. Прежняя сессия Developer должна перестать работать при следующем запросе/обновлении. После повторного входа видны оба проекта.
5. Смените этому участнику роль на Viewer. После повторного входа исчезают Resolve/Reopen. Уже открытая вкладка не может сохранить изменение с прежними правами.
6. Снимите **Active access**. После обновления участник теряет доступ; вход не даёт открыть кабинет. Снова включите доступ — прежний пароль работает, новый аккаунт не нужен.
7. У активного участника уберите все команды. После входа страницы показывают пустое состояние и подсказку обратиться к Owner. Верните Frontend, чтобы продолжить.

## Повторная отправка и отзыв

1. Пригласите `pending@example.test` как Viewer. Сохраните первую ссылку, но не регистрируйтесь.
2. Нажмите **Resend** у приглашения. В Mailpit придёт новое письмо. Первая ссылка теперь недействительна; новая открывается.
3. По новой ссылке запросите подтверждение email, откройте второе письмо и подтвердите email. До создания аккаунта снова сделайте **Resend** под Owner. Старая форма регистрации больше не должна создавать аккаунт: потребуется новая ссылка и новое подтверждение.
4. Нажмите **Revoke**. Последняя ссылка также становится недействительной. Состояние приглашения — `revoked`; ожидающие письма отменены.
5. Попробуйте повторно пригласить действующего Developer или Viewer: появится подсказка изменить доступ существующего участника. Два одновременных pending-приглашения на один email тоже запрещены.

Приглашение действует 48 часов, подтверждение email и сессия регистрации — по 15 минут. Проверки истечения и одновременного принятия покрыты автоматическими тестами; ждать вручную не требуется.

## Аутентификатор и повышение до Owner

1. У Developer/Viewer откройте **Settings → Protect your account**, подтвердите текущий пароль, добавьте ключ как time-based account в аутентификатор и введите текущий код.
2. Сохраните десять recovery codes. После включения MFA прежние сессии отозваны. Войдите заново, используя следующий TOTP-код. Теперь вход без кода запрещён.
3. Под первым Owner откройте этого участника в Members. До включения MFA вариант Owner был недоступен; теперь его можно выбрать. Сохранение снова отзывает сессии участника.
4. Войдите повышенным участником: доступны все проекты и управление Members. Отключить MFA из Settings Owner не может.
5. Для проверки последнего Owner оставьте исходный аккаунт Owner, а второго верните в Developer. Затем попробуйте понизить или отключить исходного Owner. Должна появиться ошибка **The workspace must keep at least one active Owner**; доступ исходного Owner сохраняется.
6. У вернувшегося Developer можно проверить **Disable authenticator**: нужны пароль и новый TOTP либо неиспользованный recovery code. После операции нужен новый вход; аутентификатор больше не обязателен, старые recovery codes аннулированы.

## Журнал и сохранение данных

1. У Owner в **Audit log** проверьте записи создания/изменения команд, приглашений, принятия приглашения, изменения доступа и MFA. Паролей, TOTP-ключей и ссылок приглашения там нет.
2. Выполните `yarn local:stop`, затем `yarn local:start`.
3. Войдите прежними аккаунтами: команды, роли, проекты, приглашения и локальные письма сохранены. Setup повторно не предлагается.

Ручной браузерный сценарий этой доработки оставлен для самостоятельной проверки. Автоматические результаты указаны в [testing.md](testing.md).
