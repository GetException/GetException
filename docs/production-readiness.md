# Проверка первой production-версии · 1 октября 2026

## Решение

**Подключение production-приложения пока блокируется.** Прикладные исправления опубликованы в ветке `audit/production-readiness-2026-10-01`, commit `7dec6c4`, поверх `a900d14`; сервер и npm-пакеты этой версией не обновлялись. Linux Checks этого commit прошёл. Открыты вопросы инфраструктурных образов, внешнего backup и проверки опубликованного выпуска.

Проверка сопоставляет реализацию с ADR-0001, уточнениями ADR-0002/0003, SECURITY-AUDIT, CONTEXT и планом. Осмотрены SDK/CLI, входные HTTP-границы, права БД, auth и управление доступом, обработка/хранение событий, source maps, кабинет, контейнеры и release-цепочка. Данные действующей установки проверялись отдельно от временных тестовых БД.

### Подготовка выпуска · 2 октября

Следующий патч сохраняет PostgreSQL 17 и переводит production runtime на официальный Alpine image через логическое восстановление в отдельный volume ([ADR-0004](../0004-infrastructure-runtime-upgrades.md)). Caddy 2.11.6 собирается в минимальный образ из официального checksum-проверенного бинарника. Оценка одного неприменимого zlib CVE ограничена точными компонентами и сроком; все остальные High/Critical продолжают блокировать выпуск. Обоснование и границы записаны в [image-security.md](image-security.md).

Локально подтверждены: Grype для официального бинарника Caddy 2.11.6 — без находок; лимиты proxy/upload — успешно; PostgreSQL Alpine — одна High-находка zlib с указанной оценкой, три Medium-совпадения BusyBox. Изолированная проверка на Linux Docker выполнила настоящий bookworm → Alpine перенос синтетической базы через установщик: совпали содержимое строк, Unicode, binary fields; прежний volume сохранился. Рабочая БД в этой проверке не использовалась. В обязательный Docker CI добавлены заполненная база, сохранённая сессия и повторный вход по паролю + TOTP после переноса; результат этого нового сценария должен быть подтверждён до выпуска. Отчёты готовых app/Caddy images и фактический deploy остаются отдельными Release gates.

## Исправления и удаление лишнего

- Удалены неиспользуемые SMTP worker, пакет mail, Nodemailer, Mailpit и их запуск из Compose/CI/local preview. Исторические миграции и таблицы сохранены; полномочия старой mail-роли отозваны новой миграцией. Установщик читает старые manifests, локальная конфигурация обновляется с сохранением ключей и данных.
- Вместо списка из семи запрещённых паролей используется локальный закреплённый denylist из 487 SHA-256 для допустимой длины. Это ограниченный common-password corpus; происхождение и лицензия записаны в `apps/web/THIRD-PARTY-NOTICES.md`.
- Backup при обновлении перенесён перед заменой PostgreSQL. Неудачная копия останавливает обновление до остановки действующего приложения. Незавершённый запуск БД фиксируется в журнале операции.
- Node обновлён до 24.21.0, PostgreSQL до 17.11 в прежнем семействе bookworm, Caddy до 2.11.4; registry manifests проверены и закреплены digest. У Caddy добавлены read-only root, ограниченные capabilities и временный `/tmp`.
- Исправлены устаревшие E2E-шаги ввода TOTP и проверки стека; готовность Caddy проверяется HTTPS-запросом вместо фиксированной задержки.
- Исправлено рассогласование фильтров с URL после клиентской навигации: сброс фильтров действительно сбрасывает поля формы, включая Environment.
- Обновлены документы с прежними сроками retention, schema version, SMTP и способом восстановления карт. Private source maps не предлагается публиковать в CI artifacts.

По отдельному запросу пользователя из действующей БД удалены **14 issues, 33 events и 33 inbox records** с пересчётом счётчиков. В эту сумму входят три явно указанные `R / fetch:failed`. Контрольный запрос подтвердил оставшиеся TypeError (1 event) и SyntaxError (2 events). Проекты, релизы, source maps и аккаунты сохранены.

## Открытые блокеры

### 1. Инфраструктурные образы

Обновления тегов недостаточно. Числа ниже — совпадения «пакет + advisory», а не количество доказанных способов эксплуатации:

| Проверенный официальный image                     |               Critical | High | Решение                                                                                                                     |
| ------------------------------------------------- | ---------------------: | ---: | --------------------------------------------------------------------------------------------------------------------------- |
| PostgreSQL 17.11-bookworm, закреплённый в Compose | 28 (9 разных advisory) |  103 | Выпуск блокируется. Есть системные библиотеки без исправления в bookworm.                                                   |
| Caddy 2.11.4-alpine                               |                      0 |   13 | Выпуск блокируется. В binary Go 1.26.3, старые grpc/x/text; также zlib.                                                     |
| PostgreSQL 17.11-trixie, исследованный кандидат   |                      1 |   89 | Не принят: смена Debian сама по себе не закрыла gate и требует проверки collation/reindex и восстановления.                 |
| Node 24.21.0-alpine3.24, исходная база            |                      0 |    8 | Это ещё не app image: npm/Corepack/Yarn удаляются, Alpine обновляется в Dockerfile. Требуется скан готовых четырёх образов. |

Например, Debian подтверждает уязвимую glibc bookworm для [CVE-2026-5450](https://security-tracker.debian.org/tracker/CVE-2026-5450), оценивая её как minor issue без DSA; это отличается от Critical в каталоге сканера. Для Go исправления [GO-2026-5026](https://pkg.go.dev/vuln/GO-2026-5026) требуют более новой toolchain. Доступность конкретного уязвимого пути нужно рассматривать отдельно; глобальные исключения сканера не добавлены. Актуальная версия PostgreSQL устраняет собственные старые CVE сервера/pg_dump, но не все CVE дистрибутива. [PostgreSQL security](https://www.postgresql.org/support/security/17/).

Следующий инфраструктурный выпуск требует проверенной исправленной сборки либо разбора оставшихся advisory с узким обоснованием применимости. Произвольная смена libc/дистрибутива поверх существующего volume и принятие всех `wont-fix` не считаются исправлением. Новый release gate блокирует установщик до успешного сканирования.

### 2. Внешний backup

Пользователь подтвердил отсутствие хранилища. На сервере есть только локальные копии, ежедневного offsite timer нет. Нужны bucket, раздельные writer/restore credentials, сохранение трёх последних успешных объектов, alert при отсутствии свежей копии более 30 часов, первое скачивание и восстановление. Код и точные шаги подготовлены в [backups.md](backups.md). Ключи в чат не передаются.

### 3. Проверка выпуска и среды

- Linux Docker build/start/upgrade/rollback и restore зашифрованного dump уже подтверждены Checks для `7dec6c4`. После устранения image findings должны пройти gates опубликованных SDK/registry и опубликованного bootstrap в Release.
- На осмотренном сервере опубликованы только 22/80/443, runtime-порты и PostgreSQL закрыты. SSH password/KbdInteractive login выключены, root допускается по ключу. Host INPUT policy — ACCEPT; нужна проверенная firewall policy с сохранением SSH и Docker networks.
- Шифрование диска провайдером не подтверждено. Отсутствие crypt device внутри VM не доказывает отсутствия provider encryption.
- GitHub workflow token по умолчанию read-only. Ветка `stable` не защищена. Нужна защита от force push/удаления и обязательные проверки, согласованные с текущим release bot, который создаёт version commit; произвольное включение branch policy может сломать автоматический выпуск.
- SLO ingest p95 ≤200 мс и списка issues p95 ≤1,5 с необходимо измерить на целевом/изолированном Linux-стенде при расчётном объёме. Выполненный локальный всплеск подтверждает сохранность принятых событий, а не production SLO.

## Принятые ограничения продукта

Полное соответствие Sentry, tracing/replay, email/password reset, сброс MFA и восстановление при потере всех факторов не входят в принятый контракт первой версии. Backup не заменяет потерянный TOTP/recovery-код. Эти ограничения должны оставаться явными при подключении приложения.
