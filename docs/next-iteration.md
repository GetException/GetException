# Условия первого production-подключения

Актуальная схема — 10. Реализованы ручные приглашения, обязательный MFA, доступ по командам, ротация DSN, приватные source maps, GitLab CI-контекст и retention. SMTP runtime удалён. SDK/CLI публикуются общей release-цепочкой.

## Обязательные эксплуатационные пункты

- Закрыть обнаруженные High/Critical в инфраструктурных образах и пройти сканирование итоговых images. Актуальные upstream tags сами по себе не проходят gate; результаты и проверенный альтернативный PostgreSQL image — в [production readiness](production-readiness.md).
- Подключить внешнее S3-совместимое хранилище. На 1 октября 2026 его ещё нет. Настроить отдельные write/read credentials, immutable conditional writes, versioning, retention трёх последних успешных копий и оповещение о пропусках.
- Выполнить первое скачивание и восстановление зашифрованной копии по [инструкции](backups.md), затем включить ежедневный timer. Локальный `.dump` на production host не заменяет внешнюю копию.
- Подтвердить host firewall и provider disk encryption. При аудите снаружи слушали только 22/80/443, но INPUT policy на host была ACCEPT; отсутствие guest crypt device не доказывает отсутствие шифрования у провайдера.
- Перед выпуском пройти полный `yarn checks`, HTTPS E2E, проверки исходящих изменений/секретов и Linux Docker/registry/bootstrap gates. Новая миграция требует совместимой версии приложений; схема 9 поверх 10 не запускается.
- Зафиксировать нагрузочную проверку ingest и UI на целевом сервере/изолированном стенде. В PostgreSQL есть общий лимит проекта и счётчик отказов; объёмный сетевой DDoS требует ограничений со стороны edge/provider.

## Ограничения первой версии

Password reset, MFA reset, offline recovery при потере всех факторов и уведомления об ошибках остаются за пределами принятого контракта. Восстановление backup не заменяет потерянный аутентификатор. Операторское восстановление доступа требует отдельного решения по [ADR-0002](../0002-manual-invitations-mandatory-mfa.md).

Карты не сохраняются в CI artifacts. При необходимости их восстанавливают доверенной сборкой исходного commit с теми же зависимостями либо из отдельно защищённой копии private volume. Диагностический контекст уже обработанных событий сохраняется в PostgreSQL.
