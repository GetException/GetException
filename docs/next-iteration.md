# Следующая минимальная итерация

Ближайший шаг — выпустить подготовленные изменения диагностики, source maps и интерфейса релизов через существующий release pipeline. Перед push проверить весь отправляемый диапазон и секреты; перед обновлением сервера должны пройти Linux Docker/registry/bootstrap jobs. Для первого выпуска `@getexception/cli` проверить успешную публикацию нового пакета. Миграции поднимают схему до 6, сохраняя данные; обновление выполняется с резервной копией БД по [инструкции](deployment.md).

После выпуска обновить SDK в account, подключить генерацию и приватную загрузку карт, регистрацию окружения/MR из CI и передачу структурированных API-полей по [инструкции диагностики](event-diagnostics.md). Проверить реальную ошибку в исходном коде приложения, восстановленный стек и разделение production/preview. Обеспечить восстановление карт: отдельная копия private volume либо закрытые CI-артефакты для повторной загрузки. Автоматический backup сейчас включает только PostgreSQL.

Затем проверить прекращение worker во время lease, восстановление внешнего backup и нагрузку до квоты/backlog. Добавить bounded cleanup истёкших auth/setup/session/invitation-enrollment записей, receipt compaction, реальный rejected counter и проверенный общий edge rate limiter. Подготовить процедуру хранения/ротации ключей; для сервера используется отдельный `deploy/compose.yaml`.

Реализованы команды, управление Member, ручные одноразовые приглашения Developer/Viewer, обязательный TOTP каждой роли и серверный доступ по командам. SMTP больше не участвует в auth flow; старый worker временно сохранён для отката. Дополнительный Owner назначается существующим Owner, а последний активный Owner защищён от отключения и понижения. Ручная приёмка: [сценарий](manual-testing-members.md).

Следующий функциональный шаг — утверждённое операторское восстановление пароля/MFA без email bypass, включая offline recovery единственного Owner. Затем ротация DSN.

CLI/source map upload и symbolication реализованы; интеграция CI приложения описана в [event-diagnostics.md](event-diagnostics.md). Следом — уведомления. Защищённая публикация SDK уже включена в подготовленный release workflow. Эти модули пока не содержат заглушек, обещающих готовое поведение.
