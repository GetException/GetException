# Промпт для account: версия приложения

Выполнить после публикации совместимых SDK/CLI GetException. Версия 0.1.21 ещё не поддерживает `appVersion`.

```text
Доработай существующую интеграцию GetException: нужно передавать номер версии приложения, например 3.192.75.

SDK и отправка ошибок уже подключены. Сохрани текущую интеграцию, обработку ошибок, source maps и независимость build/deploy от доступности GetException.

1. Найди, откуда существующая сборка получает номер версии account. Используй этот же источник. Не вычисляй другую версию специально для мониторинга и не используй версию npm-пакета GetException.

2. Передай номер как необязательное поле appVersion:
   - в GetException.init({ ...существующие настройки, appVersion });
   - в deployWithGetException({ ...существующие настройки, appVersion }) из @getexception/cli/integration.

   Номер должен совпадать для браузерного приложения и регистрации его сборки в CI. Если версия недоступна, поле отсутствует; это не должно мешать запуску, сборке или деплою.

3. Поле release сохрани в текущем виде account@<полный SHA>. Нельзя заменять его номером 3.192.75: SHA нужен для точного сопоставления source maps. Environment, namespace JS-файлов и привязку MR тоже сохрани.

4. appVersion — номер приложения в формате major.minor.patch, с допустимым semver-суффиксом, максимум 64 символа. Не передавай произвольные строки, ссылки или другую информацию. Не добавляй новые секреты GitLab: номер версии не является секретом.

5. Проверь доступную опубликованную версию @getexception/react (либо используемого browser SDK) и @getexception/cli и обнови до версии с поддержкой appVersion. Существующая 0.1.21 этого поля ещё не поддерживает. Если совместимой версии пока нет, подготовь изменение и явно сообщи, что обновление зависимостей ожидает публикации; не используй фиктивную версию, any или отключение TypeScript.

6. Определение «новая ошибка в релизе» выполняет GetException. В account не нужны сравнение релизов, флаг isNew или дополнительная отправка истории.

Проверь production и MR: номер передаётся одинаково, разные SHA остаются разными сборками, ошибки продолжают отправляться без source maps и при недоступности регистрации релиза. Проверь, что неизвестная/неправильная версия не блокирует обычную сборку. В логах не должно быть токенов, DSN или содержимого ошибок.

Не коммить и не пушь без моей отдельной команды. В конце перечисли изменения и проверки.
```
