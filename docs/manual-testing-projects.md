# Проверка управления проектами

Используйте отдельный тестовый проект. Входить нужно существующим Owner; повторная регистрация не требуется.

1. Создайте проект с origin `http://localhost:8080`, сохраните DSN и отправьте событие с `environment: "development"`.
2. Откройте Projects → проект → Project settings. Добавьте отдельной строкой `http://localhost:3000` или точный HTTPS origin своего приложения, нажмите Save changes. Старые origins оставьте в списке, если они ещё нужны.
3. Отправьте событие с добавленного origin с прежним DSN. Удалите этот origin из списка и сохраните: следующие события оттуда должны отклоняться. Остальные разрешённые origins продолжают работать.
4. Измените имя и slug. После обновления страницы значения сохраняются, UUID проекта, DSN и собранные события остаются прежними. Занятый slug, HTTP адрес внешнего сайта, wildcard или пустой список origins должны давать понятную ошибку без частичного сохранения.
5. В разделе Delete project введите неправильный slug: удаление отклоняется. Введите текущий slug и нажмите Delete project. Проект перемещается в Projects → Deleted projects; события через его DSN сразу перестают приниматься, а issues и releases скрываются из обычного кабинета.
6. Нажмите Restore project до указанного срока. Проект, данные, команды и прежний DSN снова доступны. Истёкшие или ранее отозванные ключи при этом не активируются.
7. Под Developer и Viewer кнопки настроек и раздел удалённых проектов недоступны. Прямые запросы изменения, удаления и восстановления должны отклоняться сервером.
8. Через пять минут после подтверждения TOTP повторите изменение. Форма должна сохранить введённые значения и предложить подтвердить пароль и новый код прямо на странице. После подтверждения повторно нажмите нужную кнопку.

После семи дней восстановление запрещено, worker-retention автоматически удаляет данные порциями до 500 записей. Очистка включает события, inbox, issues, releases, ключи, origins, связи с командами и дневную статистику. Учётные записи, команды и другие проекты остаются. Факты удаления, восстановления и окончательной очистки доступны в Audit log; содержимое удалённых событий туда не копируется. Резервные копии хранятся отдельно и истекают по политике сервера.

Истечение семи дней и полная очистка проверяются автоматически на изолированной PostgreSQL в `tests/integration/projects.test.ts`. Для ручной проверки на рабочем сервере не меняйте часы и даты в базе.
