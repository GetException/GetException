# Кабинет GetException

Текущая структура следует привычному процессу расследования ошибки: обзор состояния приложений → список групп → конкретная группа и выбранное событие. Тёмные поверхности, тонкие границы и фиолетовые акценты сохранены.

| Раздел                 | Содержимое                                                                                                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overview `/`           | События за сутки, открытые группы, регрессии, проекты, почасовой график, состояние проектов и последние релизы.                                                                          |
| Issues `/issues`       | Поиск по типу/сообщению, All/Open/Regressions/Resolved, проект, окружение, период, сортировка, фильтр релиза и пагинация.                                                                |
| Issue `/issues/:id`    | Выбранное событие, переходы Previous/Next, Resolve/Reopen, выбор stack frame, фильтр application frames, source context, сведения, теги, вкладки Events/Breadcrumbs.                     |
| Releases `/releases`   | Поиск, проект, версии из принятых событий, время получения, количество сохранённых событий. Отдельная страница релиза со связанными группами.                                            |
| Projects `/projects`   | Поиск, команды, статус и показатели. Страница проекта содержит origins, разрешённые теги, квоту, метаданные ключей и пример подключения SDK. Создание проекта остаётся отдельной формой. |
| Teams `/teams`         | Состав существующих команд и связанные проекты; поиск и пагинация.                                                                                                                       |
| Members `/members`     | Текущие участники, роль, команды, MFA, состояние доступа; поиск и пагинация.                                                                                                             |
| Audit log `/audit-log` | История входов, подтверждений, создания проекта и изменения статуса ошибок; фильтры действия и результата.                                                                               |
| Settings `/settings`   | Конфигурация установки, retention, сведения аккаунта и подтверждение пароля/TOTP для чувствительных действий. Старый `/security` перенаправляет сюда.                                    |

Resolve закрывает группу и сбрасывает Regression. Новое событие в закрытой группе открывает её как Regression. Reopen открывает вручную без признака повторной ошибки. При поступлении события после загрузки страницы Resolve возвращает сообщение с предложением обновить данные. Изменения статуса фиксируются в audit атомарно.

Счётчик группы хранит всю историю. Списки событий, связи групп с релизами и окружениями основаны на сохранённых событиях за период retention (30 дней). Фильтр периода в Issues применяется к последнему появлению группы, число Events показывает общий счётчик группы. Для расследования более старых групп доступны агрегаты и понятное состояние отсутствующих событий.

Списки имеют по 25 строк, события — 20, команды — 12. Параметры и сортировка ограничены сервером; после 200 страниц поиск нужно сузить. График обрабатывает максимум 25 000 событий за сутки и сообщает об усечении. Меню на узком экране отображает значки с доступными именами; широкие таблицы прокручиваются внутри панели.

Owner создаёт и редактирует Teams, назначает участников и проекты, меняет роли и активность в Members. Здесь же находятся приглашения, статусы доставки и Resend/Revoke. Members и Audit log видны только Owner; Developer/Viewer видят проекты своих команд. Resolve/Reopen доступны Owner и Developer. Settings позволяет подключить или отключить добровольный MFA; Owner отключить его не может. Принятие приглашения вынесено в `/invite`, `/invite/verify`, `/invite/register`. Source maps и symbolication ещё отсутствуют: стек показывает реальные compiled frames, Source context явно сообщает об отсутствии исходников. Browser/OS и affected users не выводятся: текущий безопасный формат события этих данных не хранит. Заглушки с вымышленным кодом, пользователями или статистикой отсутствуют.

DSN показывается однократно при создании проекта. Страница проекта содержит только метаданные ключей и placeholder в примере SDK; секреты, хеши и исходные payload не передаются в интерфейс.

Перед запуском обновлённого web/worker примените `yarn db:migrate` с ролью migrate. Миграция `202609080003_issue_workflow` добавляет права UPDATE только двух колонок и обновляет триггер Regression/readiness; сохранённые проекты и события не удаляются. В Compose отдельный сервис migrate выполняет это при запуске.

Приглашения требуют миграцию `202609080004_members_invitations`. Подробности: [почта](mail.md), [сценарий проверки](manual-testing-members.md).
