# Ручные приглашения и почтовая инфраструктура

Актуальный контракт задан [ADR-0002](../0002-manual-invitations-mandatory-mfa.md). GetException больше не отправляет письма для приглашений, подтверждения email или восстановления доступа. SMTP не нужен ни для первой установки, ни для добавления участников.

## Приглашение

Owner подтверждает пароль и новый TOTP-код в Settings, затем в Members выбирает email, роль Developer/Viewer и команды. Сервер возвращает персональную ссылку только один раз. Owner копирует её и передаёт ожидаемому человеку через доверенный личный канал.

Ссылка содержит 256 случайных бит во fragment URL и действует 24 часа. Сервер хранит только SHA-256 хеш. Fragment удаляется из адресной строки после чтения и уходит серверу только в JSON body. Повторно получить действующий секрет нельзя: **Reissue link** создаёт новый токен и немедленно инвалидирует старый токен и незавершённую регистрацию. **Revoke** отзывает приглашение.

Email является назначенным Owner идентификатором входа. GetException не проверяет владение почтовым ящиком. Безопасность первичной передачи зависит от выбранного канала: не публикуйте ссылку в общем чате, issue, логе или задаче с широким доступом.

## Регистрация и обязательный MFA

Новый пользователь задаёт имя и пароль, получает отдельный TOTP secret и подтверждает первый код из Google Authenticator или другого совместимого приложения. До правильного кода User, Account, Member и TeamMember не создаются. После проверки они создаются одной транзакцией вместе с активным TOTP credential и хешами recovery-кодов.

TOTP обязателен для Owner, Developer и Viewer. Существующий участник без MFA после проверки пароля получает только 15-минутную сессию настройки; dashboard и его API остаются закрыты. Вход разрешён с паролем и новым TOTP-кодом либо одним неиспользованным recovery-кодом. Критичные Owner-действия требуют password + TOTP step-up не старше пяти минут.

Recovery-коды показываются один раз. Email reset отсутствует. Потеря аутентификатора и всех recovery-кодов в текущей итерации требует операторского восстановления из проверенного backup; автоматического обхода второго фактора нет.

## Совместимость после обновления

Миграция `202609260009_manual_invitations_mandatory_mfa` истекает старые pending email-приглашения, удаляет verification sessions и очищает зашифрованные payload ожидающих писем. Создайте новые ручные ссылки после обновления.

Таблица outbox, роль `getexception_mail`, worker-mail и переменные `MAIL_*`/`SMTP_*` пока остаются в deployment bundle для совместимого обновления и отката на предыдущую версию. Новый web-код не создаёт почтовые задания. Эти компоненты можно удалить отдельной миграцией после завершения окна отката.

Локальный Mailpit также остаётся доступен старым релизам через `yarn local:mailpit`, но актуальный сценарий приглашений его не использует.
