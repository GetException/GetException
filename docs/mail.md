# Приглашения и доставка почты

## Постоянный локальный запуск

`yarn local:mailpit` один раз скачивает официальный Mailpit 1.31.1, проверяет закреплённый SHA-256 для текущей платформы и сохраняет бинарник в `.artifacts/tools/mailpit`. Можно указать собственный проверенный `MAILPIT_BINARY`. На этом рабочем месте бинарник уже подготовлен. Обычный `yarn local:start` ничего не скачивает и не пересобирает.

Runner запускает Mailpit и отдельный `worker-mail` автоматически. Письма для любых тестовых email попадают только в Mailpit; внешнего SMTP и relay нет. Ящик хранится в `runtime/local/mailpit.db` и переживает остановки. В конфигурации появляются независимые пароль роли `mail`, ключ `MAIL_ENCRYPTION_KEY` и почтовые порты. Конфигурация предыдущей версии обновляется автоматически с сохранением старых ключей, портов и данных; роль mail добавляется перед миграцией. Весь `runtime/local`, включая письма со ссылками приглашений, остаётся вне Git.

Новый Developer/Viewer проходит приглашение, подтверждение email и задаёт пароль. TOTP для них добровольный. Для Owner он остаётся обязательным. Подробный [сценарий проверки](manual-testing-members.md) проходит весь путь через локальные письма.

## Серверный контракт

Production можно впервые запустить без SMTP с `MAIL_ENABLED=false`. Регистрация Owner через bootstrap, TOTP/recovery codes, вход и работа с проектами не зависят от доставки писем. Members и Settings показывают отключённую почту. Сервер отклоняет создание, повторную отправку и принятие приглашений, включая этапы проверки email и регистрации; отзыв ранее созданного приглашения остаётся доступным Owner с step-up. Токены не выдаются вручную и подтверждение почты не обходится.

При отключённой доставке worker-mail обслуживает health endpoints с `mailEnabled: false`, но не создаёт SMTP transport и не забирает outbox. Ожидающие письма не теряют попытки; при включении доставки остаётся обычная проверка срока и ревизии. Чтобы подключить почту позже, сохраните базу и ключи, задайте SMTP и `MAIL_ENABLED=true`, затем примените конфигурацию по [инструкции установки](deployment.md). Отсутствие флага сохраняет прежний включённый режим для существующих установок и локального Mailpit.

`InvitationService` сохраняет нормализованный email, роль Developer/Viewer и снимок нескольких команд. Создание, повторная отправка и отзыв требуют Owner с TOTP не старше пяти минут. Ссылка содержит 256 случайных бит во fragment; браузер убирает fragment и передаёт токен только в POST body. Публичный preview маскирует email и не раскрывает наличие аккаунта. Токены приглашения (48 часов), подтверждения email (15 минут) и регистрации (15 минут) хранятся как хеши.

Новая регистрация требует отдельного подтверждения владения почтой и HttpOnly cookie до приёма пароля. Account, credential, Member и TeamMember создаются одной транзакцией с потреблением приглашения. Существующий аккаунт должен войти с совпадающим verified email; существующее членство не перезаписывается. Resend меняет токен и ревизию, аннулирует proof/session. Revoke отменяет ссылки и ожидающие письма.

Outbox содержит AES-256-GCM ciphertext с отдельным `MAIL_ENCRYPTION_KEY`; AAD связывает сообщение с ID и ревизией. `getexception_mail` имеет только SELECT/UPDATE outbox и SELECT runtime_schema, без доступа к auth, memberships, invitation и событиям. Worker claim использует SKIP LOCKED, lease token и ревизию. Отправка удерживает блокировку актуального сообщения при ограниченном восьмисекундном SMTP I/O. Успех, отмена и окончательный отказ очищают payload. Повторные попытки ограничены пятью; ошибки сохраняются фиксированными кодами. После сбоя между SMTP и commit письмо может прийти повторно, но доступ нельзя принять дважды.

Настройки SMTP доступны только worker-mail; web знает только ключ outbox. SMTP клиент — Nodemailer 9.1.1 (MIT), типы — `@types/nodemailer` 8.0.1. Версия прошла существующий Yarn age gate без обхода quarantine. Настройки транспорта: [официальная документация Nodemailer](https://nodemailer.com/smtp). Локальный catcher Mailpit 1.31.1 (MIT): [параметры запуска](https://mailpit.axllent.org/docs/configuration/runtime-options/).

## Compose и внешний SMTP

Свежий `yarn local:env` создаёт `MAIL_PASSWORD` и `MAIL_ENCRYPTION_KEY` вместе с остальными независимыми секретами. PostgreSQL init создаёт роль mail, миграция `202609080004_members_invitations` выдаёт ей минимальные права. Mailpit UI публикуется только на `127.0.0.1:8025`, SMTP-порт наружу не публикуется. Почтовая сеть internal, внешней доставки по умолчанию нет.

Для внешнего SMTP нужны `MAIL_ENABLED=true`, параметры `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, при необходимости `SMTP_USER`/`SMTP_PASSWORD`, а также разрешённый сетевой выход worker-mail. Выберите `SMTP_MODE=starttls` или `tls`; TLS проверяет сертификат сервера. Режим `local` разрешён только для localhost/127.0.0.1/mailpit. SMTP-секреты не передаются web, ingest или event worker. Production Compose проверяется в CI; доступ к конкретному внешнему SMTP проверяется при его подключении.

Существующий Compose volume требует добавления роли mail до новой миграции; PostgreSQL init scripts повторно не выполняются. Не удаляйте volume и не заменяйте существующие ключи. Нативный `yarn local:start` выполняет это обновление автоматически и не использует Docker `.env`.
