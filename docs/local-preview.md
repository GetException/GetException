# Постоянный локальный запуск без Docker

Для ручного просмотра используйте `yarn local:start`. Этот запуск сохраняет PostgreSQL, аккаунт Owner, MFA, проекты, события, ключи приложения и локальный TLS CA между остановками. Повторный setup не требуется. Автоматические integration/E2E-тесты по-прежнему используют независимые временные базы.

Нужны Node 24.4.0, Yarn 4.17.1, установленные зависимости и проверенный Caddy 2.10.2 в `.artifacts/tools/caddy` либо путь `CADDY_BINARY`. PostgreSQL берётся из уже закреплённого dev-пакета; устанавливать системный сервер не нужно. Запускайте обычным пользователем на macOS/Linux.

```bash
nvm use
yarn local:mailpit
yarn checks
yarn local:start
```

Постоянные адреса по умолчанию:

- кабинет: `https://monitor.localhost:8443`;
- ingest: `https://ingest.monitor.localhost:8443`;
- browser fixture: `https://browser.monitor.localhost:8443`;
- React fixture: `https://react.monitor.localhost:8443`;
- локальная почта: `http://127.0.0.1:8025` (точный адрес runner печатает при запуске).

Все процессы этого режима слушают только `127.0.0.1`. Сертификат локальный; root certificate лежит в `runtime/local/caddy-data/caddy/pki/authorities/local/root.crt`. Доверие к этому сертификату пользователь настраивает для своей тестовой установки средствами ОС/браузера. Сохранение CA предотвращает его замену при каждом старте.

Только при первой настройке откройте `/setup`, возьмите токен из `runtime/local/setup-token`, задайте email/пароль и подключите приложение-аутентификатор. Installation domain — `monitor.localhost`, без порта. После setup сохраните recovery codes и удалите локальный setup-token; после следующего запуска файл также удаляется автоматически. Новые запуски не открывают setup повторно и не меняют шифровальные ключи.

Остановка: Ctrl+C в терминале запуска или отдельная команда из корня:

```bash
yarn local:stop
```

Повторный запуск — `yarn local:start`. Действующая сессия сохраняется в пределах её срока; при новом входе нужны прежние email/пароль и актуальный код из уже подключённого аутентификатора. Проекты, DSN и allowed origins не нужно создавать заново: HTTPS-порт также сохраняется.

Данные находятся в **`runtime/local`**, который исключён из Git:

| Путь                         | Содержимое                                                                                                                        |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `data/`                      | Постоянный PostgreSQL cluster.                                                                                                    |
| `config.json`                | Сохранённые порты, независимые пароли PostgreSQL-ролей, ключ подписи сессий, ключ шифрования MFA и ключ rate-limit. Права `0600`. |
| `caddy-data/`                | Локальный TLS CA и сертификаты.                                                                                                   |
| `setup-token`                | Одноразовый токен до завершения setup.                                                                                            |
| `address.json`               | Адреса кабинета и fixtures.                                                                                                       |
| `runner.pid`, `control.sock` | Блокировка повторного запуска и локальный канал остановки.                                                                        |

Остановка удаляет только служебную блокировку и сокет. Она не удаляет данные или ключи. Для резервной копии остановите приложение и сохраните весь `runtime/local`: одной базы недостаточно для расшифровки MFA. Если конфигурация пропала при существующей базе или база пропала при сохранённой конфигурации, runner отказывается создавать замену. Автоматического reset нет.

Миграции применяются при каждом старте ролью migrate; пароли существующих ролей и ключи не пересоздаются. Ошибки запуска сохраняют данные. Если выбранный порт занят, runner сообщает об этом и оставляет адреса прежними. `LOCAL_HTTPS_PORT` позволяет выбрать другой порт **при первом создании** локальной установки; для существующей используются сохранённые значения.

Перед первой проверкой на новом компьютере выполните `yarn ci:tools`. После изменений исходников остановите приложение, выполните `yarn checks` и снова `yarn local:start`: этот режим запускает проверенную production-сборку. Он не использует Docker `.env`, не передаёт NPM_TOKEN дочерним процессам и не читает данные автоматических тестов. Старый `.artifacts/preview.ts` с временной базой больше не следует использовать для ручного просмотра.
