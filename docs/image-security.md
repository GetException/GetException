На 1 октября 2026 Docker tags Node 24.21.0, PostgreSQL 17.11-bookworm и Caddy 2.11.4-alpine опубликованы. В обоих Compose закреплены одинаковые SHA-256 image indexes; наличие linux/amd64 и хеш тела manifest проверены через официальный registry. PostgreSQL остаётся на major 17. Его прежняя 17.6 пропускала последующие исправления безопасности, включая сервер и pg_dump. [PostgreSQL 17 security](https://www.postgresql.org/support/security/17/), [Caddy 2.11.4](https://github.com/caddyserver/caddy/releases/tag/v2.11.4), [Node 24.21.0](https://nodejs.org/en/blog/release/v24.21.0).

Отчёты [релиза 38fdf19](https://github.com/GetException/GetException/actions/runs/34397031356) подтвердили отсутствие Critical во всех пяти образах. Они также обнаружили две High-находки только в зависимостях Prisma CLI в migrate. Для `@prisma/config/deepmerge-ts` закреплена 8.0.2 через Yarn resolutions (GHSA-ggr8-5vv4-36mx), для `prisma/mysql2` — 3.23.1 (High GHSA-3f6p-5ww8-9rcr и Medium GHSA-rgwj-5xj2-c3m3). Это ограниченные переопределения зависимостей Prisma 7.10.0, а не исключения сканера. Их следует убрать, когда поддерживаемая версия Prisma сама перейдёт на исправленные зависимости. Новая major deepmerge меняет слияние Map; наш `prisma.config.ts` использует обычные объекты и строки. Совместимость проверяется генерацией клиентов и настоящими миграциями в `yarn checks`, затем установкой/обновлением в Docker CI.

В историческом отчёте оставалась Medium CVE-2025-60876 в BusyBox 1.37.0-r31: сканер считает её для `busybox`, `busybox-binsh` и `ssl_client`. Это одна уязвимость обработки URL в BusyBox wget, а не три независимые ошибки приложения. Исправленная версия для выбранной Alpine в отчёте пока не указана. Серверные приложения и мигратор не передают пользовательские URL в wget; сетевые вызовы выполняют Node-библиотеки. Находка остаётся видна в отчётах, обновление BusyBox нужно повторно проверить при обновлении базового образа. [Описание CVE](https://security-tracker.debian.org/tracker/CVE-2025-60876).

## Проверка выпуска

`Release` сканирует четыре образа приложения (web, ingest, worker, migrate), собственный минимальный Caddy и PostgreSQL с обновлёнными системными пакетами по digest с `--fail-on high`. Ошибка сканера либо неразобранная High/Critical/Unknown-находка блокирует публикацию установщика. Полные исходные JSON-отчёты и отдельный результат оценки доступны в artifacts `vulnerabilities-<target>`, включая неуспешные запуски. Снижение порога, скрытие пакетов и глобальный `ignore-unfixed` не используются.

Обновление состава образов само по себе не является успешным результатом сканирования: завершённую проверку нужно смотреть в `Release` для конкретного SHA. `yarn checks` проверяет приложение, миграции и workflows; Linux CI дополнительно проверяет настоящие контейнеры, Owner/TOTP, приём событий, сохранение данных и восстановление backup.

Все шесть runtime-образов входят в `build-images`; каждый готовый digest сканируется до записи manifest. Успех всех проверок обязателен для `publish-bootstrap`. Проверить опубликованный PostgreSQL локально можно через `python3 scripts/release/install-tools.py grype` и `python3 scripts/release/scan-image.py --target postgres --image ghcr.io/getexception/getexception-postgres@sha256:<digest>`. Состояние проверок конкретного рабочего дерева фиксируется в [production readiness](production-readiness.md).

## Уточнение от 2 октября 2026

Используются официальный PostgreSQL 17.11 Alpine 3.24 по digest и официальный статический Caddy 2.11.6 (Go 1.26.8, grpc 1.83.2, x/text 0.42.0). В образ Caddy копируются только проверенный по SHA-256 бинарник, его лицензия и CA roots. Готового upstream Docker tag 2.11.6 на момент проверки нет. Смена PostgreSQL runtime выполняется через отдельный volume и логическое восстановление по [ADR-0004](../0004-infrastructure-runtime-upgrades.md); старый glibc PGDATA не подключается к musl.

Единственная оценённая неприменимость — **CVE-2026-85091**, пакет Alpine `zlib 1.3.2-r0`, для PostgreSQL 17.11 и Node 24.21.0 в web/ingest/worker/migrate. Уязвимость требует сочетания non-blocking `gzwrite` со следующим `gzprintf`/`gzvprintf` после остановки записи. Это не уязвимость распаковки gzip/`inflate`. [Описание CNA](https://www.cve.org/CVERecord?id=CVE-2026-85091).

Наш backup использует только PostgreSQL custom format (`pg_dump -Fc`), реализованный через `deflate`/`inflate`; file API `gzprintf`/`gzvprintf` в этом коде не используется. [Исходник PostgreSQL 17.11](https://github.com/postgres/postgres/blob/REL_17_11/src/bin/pg_dump/compress_gzip.c). Node binding также вызывает streaming compression API, а не неблокирующий gzip file writer; приложение использует `node:zlib` для ограниченной распаковки. [Исходник Node 24.21.0](https://github.com/nodejs/node/blob/v24.21.0/src/node_zlib.cc). SQL пользователя, произвольные shell-команды и расширения PostgreSQL через продукт не исполняются. Это вывод о недостижимости описанного пути в текущей конфигурации, а не утверждение об исправлении zlib.

`scan-image.py` ограничивает оценку одним CVE, точным именем/типом/версией пакета и целевыми образами. Другие CVE, версия пакета, образ Caddy, внешние scanner exclusions или повреждённый отчёт блокируют выпуск. Смена закреплённой базы PostgreSQL либо версии Node требует нового review. Оценка истекает **2 ноября 2026**; после этого та же High-находка снова блокирует выпуск. Исходный отчёт продолжает показывать High, отдельный assessment объясняет результат gate. Если появятся новые native bindings, non-blocking gzip file writer либо другой формат backup, оценку необходимо пересмотреть раньше.

Источники: [исправления Node.js](https://nodejs.org/en/blog/vulnerability/december-2025-security-releases), [официальные теги Node Docker](https://github.com/docker-library/official-images/blob/master/library/node), [glibc в Debian](https://security-tracker.debian.org/tracker/CVE-2026-5450), [Perl в Debian](https://security-tracker.debian.org/tracker/CVE-2026-8376), [OpenSSL](https://security-tracker.debian.org/tracker/CVE-2026-75803), [Nodemailer 9.1.1](https://github.com/nodemailer/nodemailer/releases/tag/v9.1.1), [Prisma Docker](https://www.prisma.io/docs/guides/deployment/docker), [Argon2 Alpine](https://github.com/ranisalt/node-argon2#prebuilt-binaries).

## Исправление OpenSSL от 6 октября 2026

[Release 37493796470](https://github.com/GetException/GetException/actions/runs/37493796470) заблокирован четырьмя CVE OpenSSL 3.5.8 в официальном PostgreSQL: CVE-2026-54873, CVE-2026-84782, CVE-2026-84784 и CVE-2026-72897. Исправленная версия OpenSSL 3.5.9 опубликована в Alpine 3.24. PostgreSQL runtime теперь собирается из прежнего официального digest с обновлением системных пакетов и сканируется после сборки, как образы приложения. Исключения для OpenSSL не добавляются. PostgreSQL 17.11, его entrypoint и поколение volume не меняются; политика единственной ранее рассмотренной находки zlib и её срок остаются прежними. [Официальное исправление OpenSSL](https://openssl-library.org/news/secadv/20260929.txt).
