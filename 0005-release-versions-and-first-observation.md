# Отделить номер приложения от идентификатора сборки и сохранять первое наблюдение ошибки

Релиз остаётся неизменяемым `application@<full Git SHA>`, чтобы preview-коммиты с одинаковой версией приложения не смешивали карты. Необязательное `appVersion` является метаданными отображения: SemVer до 64 символов, передаётся SDK и регистрацией CI. Авторизованная регистрация CI имеет приоритет над номером из недоверенного события; browser-события не переписывают уже известный номер релиза. Отсутствие или неверный номер в SDK/интеграции не блокирует приложение и не отменяет доставку ошибки.

«Новая в релизе» означает первое серверное наблюдение группы в этом окружении, а не доказательство причинного изменения кода и не статус `regression`. История сохраняется независимо от 30-дневных событий и групп, с 90-дневным сроком после последней активности по ADR-0003. Первое событие без release оставляет первый релиз неизвестным; следующее событие с release не становится первым. Порядок завершения worker не меняет хронологию; повтор задания не создаёт второе наблюдение. При однозначном изменении fingerprint из-за source maps переносится прежняя история, без фиктивного нового появления. Если одна исходная группа разделилась между несколькими группами, неподтверждённое первое появление остаётся неизвестным; алиас не направляет будущие события в произвольную часть группы.

При миграции сохраняются наблюдения из доступных событий. Старые группы получают признак неполной истории: отсутствующие события невозможно восстановить. Граница начала регистрации истории хранится у проекта, чтобы первое наблюдение в новом окружении старой группы не выдавалось за доказанно новое. После полного 90-дневного окна работы история вновь достаточна для утверждений в пределах этого окна. Все выборки истории подчинены существующему доступу к проекту; ingest не получает доступа к истории, релизам или другим событиям.
